# Roadmap 1.4 — Resistance buff effects

Status: done
Roadmap: ROADMAP.org 1.4
Decisions: DECISIONS.md "Weapon weakness removed", "Buff magnitude scaling",
"Buff storage representation", "Resistance buffs"
Session: SESSION.md
Docs updated: 2026-11-21 (plan); archived 2026-11-23

Steps only, no code. Historical record: the implementation is in the source and
`SESSION.md`.

## Scope

Remove weapon weakness, apply the four resistance buff effects, and wire seeded
species variety into spawning. It does not design bespoke per-species behavior;
that is Phase 6.

## Decisions already settled

- Weapon weakness is removed; one `damage` per weapon. (DECISIONS "Weapon
  weakness removed")
- Buff magnitude is a normalized permille fraction of a per-category ceiling,
  stored per instance. (DECISIONS "Buff magnitude scaling")
- The total per category is capped additively at its ceiling. (DECISIONS "Buff
  magnitude scaling")
- Buffs live on the instance and are copied whole through the roster. (DECISIONS
  "Buff storage representation")

## Before you start

- Confirm `odin check src` is clean.
- Capture a headless same-seed log as the pre-change baseline, using the method
  from 1.3 in `SESSION.md`.
- Do not add a weapon-switching control; Neutral-only is the intended state
  until the Phase 7 skill tree.

## Steps

### A. Remove weapon weakness

**A1. Collapse weapon damage — `src/player.odin`**

- Replace the three damage tiers in `WeaponDefinition` with one `damage: int`.
- Set placeholder damage in `WEAPON_DEFS`.
- Leave `WeaponType`, textures, bullet sizes, and speed untouched.

**A2. Delete weakness from bacteria — `src/enemy.odin`**

- Remove `weakness` from `BacteriaDefinition` and its assignments in
  `BACTERIA_DEFS`.

**A3. Simplify damage resolution — `src/game.odin`**

- Delete `calculate_bullet_damage` and subtract `weapon_def.damage` directly in
  `collision_update`.
- Remove the now-unused `bacteria_def` local.
- Leave kill attribution as is.

**A4. Verify A**

- No references to weakness or the tier names remain.
- Kill counts, wave resolution, and roster behavior match the baseline.

### B. Apply buff effects

**B1. Extend the representation — `src/enemy.odin`**

- Add `BuffInstance` with category and permille fraction.
- Change the buff arrays on `BacteriaCold`, `BacteriaSpawnParams`, and
  `PendingBacteria` to `[MAX_BUFFS]BuffInstance`.
- Rename `BuffDefinition.magnitude` to `max_magnitude` and document each unit.
- Set provisional per-category ceilings.
- Extend `bacteria_buff_add` to shift whole instances.

**B2. Add the curve and cap helpers — `src/enemy.odin`**

- Add the 5-level block fraction bands.
- Add `buff_fraction_permille(level, rng)` using inclusive draws.
- Add `buff_total(cold, category)` as the only place the cap is enforced.
- Never loop the full array; the zero category is Hardy.

**B3. Apply Hardy and Frenzied at init — `src/enemy.odin`**

- Apply Hardy to `max_health`, then restore `health` from it.
- Apply Frenzied to `cold.speed` on top of `speed_scalar`.
- Add a per-life Biofilm hit counter and reset it on spawn.

**B4. Apply Resistant and Biofilm at the damage site — `src/game.odin`**

- Add a damage helper: consume a Biofilm hit and return 0, otherwise reduce by
  Resistant with a floor of 1.
- Call it from the collision path.

**B5. Roll the fraction at flee — `src/level.odin`**

- Draw the fraction from the same per-slot buff RNG, after the category draw.
- Keep the category as the first draw so existing rolls do not move.
- Leave the flee threshold's per-buff count term unchanged.

**B6. Carry magnitudes through roster and return — `src/level.odin`**

- Change the local buff types to `BuffInstance`; the existing copies then carry
  magnitudes.

### C. Wire species variety

**C1. Pick species at fresh spawn — `src/level.odin`**

- Use `Wave.species_unlocked` at the fresh-spawn branch instead of `.Strep`.
- Draw from the first `min(species_unlocked, len(BACTERIA_DEFS))` species.
- Derive a distinct seed per spawn; `.Wave, 0` is already the count jitter.
- Returners keep their stored species.

**C2. Verify C**

- Levels 1–5 spawn only Strep; level 6+ shows multiple species.
- Same seed twice: identical species per slot per wave.

## Outcome

Landed with these deviations from the plan:

- **Weapon damage.** `WEAPON_DEFS` ended with all three weapons at `damage = 3`
  rather than the planned 6/6/3. Recorded as placeholders until Phase 7; the
  weakness removal itself landed as planned.
- **Helper names.** The damage helper is `bacteria_dmg_after_buffs` in
  `src/game.odin`; the per-life counter is `biofilm_hits`.
- **Flee threading.** `wave_flee_update` did not need the level number. The
  level was threaded into `wave_update` instead, which owns the
  `wave_flee_begin` call.
- **Species draw seed.** The fixed `derive_seed(wave.seed, .Wave, 1)` would have
  given every spawn in a wave the same species. The draw uses
  `1 + wave.spawn_index`. `.Wave, 0` remains the count jitter.
- **Missing assignment.** `Wave.species_unlocked` was not populated by
  `wave_init`, despite the plan saying it was. The draw therefore called
  `int_range(0, 0)` and asserted at level 6. `wave_init` now stores
  `wp.species_unlocked`.
- **Placeholder motion pulled forward.** Enabling species variety exposed empty
  non-Strep entry/update branches: Staph, E. coli, and Pseudomonas could spawn
  but never move. Entry and return bezier movement were duplicated per species,
  `entry_path_length` is set for all four at spawn and return init, and minimal
  `Zigzag_Dive` and `Sweep_Dive` updates were added so every species dives and
  returns. These blocks are deliberate Phase 6 placeholders.
- **Dive return setup.** Every dive type now sets `return_start_points`,
  `t = 0`, `dive_initialized = false`, and `return_initialized = false` on
  entering `.Returning`. The `return_initialized` reset was not in the plan; it
  is required for a second dive in the same life, which otherwise reused the
  first return path. Latent for Strep before this step.
- **Not verified at runtime yet.** The 1.4 species and buff checks in
  `SESSION.md` are recorded as still to run.
