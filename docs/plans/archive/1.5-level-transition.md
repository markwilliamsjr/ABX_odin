# Roadmap 1.5 — Level transition

Status: done
Roadmap: ROADMAP.org 1.5
Decisions: DECISIONS.md "State machine", "Seeding"; ARCHITECTURE.md "Level
progression"
Session: SESSION.md
Docs updated: 2026-11-23

Steps only, no code.

## Scope

Make `.Level_Transition` a real, observable state: hold the completed level's
frame, show the level number, create the next level through `level_init`, and
return to `.Playing`. It also removes the unused `Level.end_chance` field. It
does not add the skill tree, persistence, `Game_Over`, or new level-scaling
rules; it changes behavior by making levels advance instead of stopping at
`level_end`.

## Decisions already settled

- `.Level_Transition` is a real state that does real work and is the designated
  mount point for the skill tree. (DECISIONS "State machine")
- The transition owns level progression: derive the next level's seed, draw its
  wave count, initialize its waves, and reset per-level state. It is the single
  place advancement happens. (DECISIONS "State machine"; ARCHITECTURE "Level
  progression")
- `world_init` performs the only initial generation; every later level is
  created by the transition. (ARCHITECTURE "Level progression")
- The pending flee roster lives on `World` and survives transitions.
  (DECISIONS "Return scope")
- Seeds chain by level number: `level_init` derives the level seed from
  `master_seed` and the level number, then draws the wave count before any wave
  is initialized. (DECISIONS "Seeding")
- `wave_resolution_update` owns per-wave advancement and sets `level_end` when
  `wave_index` reaches `wave_count`; the transition owns only what happens
  after that. (DECISIONS "Wave resolution")
- Wall-clock time must not feed generation or threshold decisions. The
  transition is display/control flow, but a `delta_time` accumulator is still
  preferred over `sdl.GetTicks` so replay timing stays frame-driven.
  (DECISIONS "Determinism")

## Steps

### 1. Remove the dead field — `src/level.odin`

- Delete `end_chance` from `Level`.
- Confirm no initializer or reader remains.

There is no behavior change. Keeping the field would leave a name that looks
like it still controls level ending, which `wave_resolution_update` and the
rolled flee threshold superseded.

### 2. Add transition state — `src/game.odin`

- Add a small `LevelTransition` struct near `World` with `elapsed: f32` and
  `duration: f32`.
- Add `transition: LevelTransition` to `World`.
- Put both in `game.odin`, beside `World` and `GameState`, so the state machine
  and its data stay in one file.

Scaffolding only: nothing reads the fields until steps 3 and 4. The struct is
the intended seam for the skill tree's hold point, so do not fold the fields
into unrelated structs.

Recommended shape:

```
LevelTransition :: struct {
    elapsed:  f32,
    duration: f32,
}
```

### 3. Enter the transition — `src/game.odin`

- In the `.Playing` branch of `world_update`, after the
  `if level.wave_index < level.wave_count` block, test `level.level_end`.
- On true: set `world.state = .Level_Transition`, reset
  `world.transition.elapsed = 0`, set `world.transition.duration` (see Open
  choices), and log `[level N] transition start`.
- Do not increment `level_number` or call `level_init` here. Generation belongs
  to the exit step.
- The state change itself prevents a second trigger: the `.Playing` branch no
  longer runs while the state is `.Level_Transition`.

`wave_resolution_update` sets `level_end` on the same frame the last wave
resolves, so the check can sit directly after the wave block without another
timer.

### 4. Advance the level — `src/game.odin`

- In the `.Level_Transition` branch of `world_update`, accumulate
  `world.transition.elapsed += delta_time`.
- When `elapsed >= duration`, in this order:
  1. capture `next := world.level.level_number + 1`
  2. call `level_init(&world.level, world.master_seed, next)`
  3. clear transient combat state (`world.bullets = {}`; see Open choices for
     the player)
  4. set `world.state = .Playing`
  5. log `[level N] transition end: next=M`
- `level_init` already resets `wave_index`, `level_end`, the bacteria pool, and
  every wave, and it does not touch `world.return_roster`.
- Guard against running twice: `level_init` sets `level_end = false`, and the
  state flip ends the branch. Do not call `level_init` from anywhere else.
- Do not accumulate while `.Paused`; the exhaustive switch already excludes it.

This is the step that consumes the struct from step 2. Until it lands, the
transition state is inert.

### 5. Render the transition — `src/game.odin`

- `.Level_Transition` already calls `render_world`, which clears and draws the
  frozen frame. Keep that call.
- After it, draw the level text centered with `update_text` and
  `game.assets.debug_font`, following `render_menu`'s pattern: a local
  `^sdl.Texture`, destroyed after `RenderCopy`.
- Use `fmt.ctprintf` or a stack-allocated cstring for the number; do not
  allocate a persistent string.
- Suggested text: `Level N cleared` / `Next: M`, or just `Level N`. See Open
  choices.

Do not add a menu or interactive prompt. The skill tree mounts here later and
will replace the text, not sit beside it.

### 6. Verify

- `odin check src` clean; no references to `end_chance`.
- Clear level 1 and watch the transition:
  - it starts exactly once
  - simulation is suspended for the whole hold
  - level 2 begins with `wave_index == 0`, `level_end == false`, a fresh
    bacteria pool, and its own wave count
- Roster: flee at the end of level 1; the entry returns in level 2's first wave
  with species and buffs intact.
- Same seed twice: level 2 composition matches, and changing the transition
  duration does not change generation.
- `--level 16` clears to level 17; `species_unlocked` advances with it.
- `--debug` starts in `.Playing` and transitions normally.
- No stale bullets carry into the next level.
- Exactly one `transition start` and one `transition end` per level; no skipped
  or repeated level.
- Render: the text draws on a frozen frame, and the per-frame texture is
  destroyed.
- Regression: wave advancement, flee phase, roster scheduling, and level-end
  logging are unchanged up to the moment the transition starts.

## Open choices

**1. Hold duration vs input.**
- Fixed duration: simple, testable, no input surface — recommended.
- Press a key to continue: gives the player control, but adds an input state
  that the skill tree will replace.
Recommendation: fixed duration for 1.5. Put it in one constant or field so the
skill tree can own it later.

**2. Reset the player or only bullets.**
- Clear bullets only: keeps the player where it was, minimal change —
  recommended.
- Reset the player to spawn: consistent opening for every level, but changes
  movement feel and is not required by 1.5.
Recommendation: clear bullets; leave `player` alone. Record the choice.

**3. Transition text.**
- `Level N` (the level just completed): matches the log.
- `Level N` (the level about to start): matches what the player is entering.
Recommendation: show the completed level and the next number, e.g.
`Level N cleared`; it is unambiguous during the hold.

**4. Where the timer lives.**
- `World.transition`: keeps all world state together and survives inside the
  world — recommended.
- `Game`: shorter reach from `world_update`? No: `world_update` already holds
  `game`, so there is no gain.
Recommendation: `World.transition`.

## Deliberately not doing

- The skill tree and its node UI — Phase 7. The seam is `LevelTransition` plus
  the `.Level_Transition` state; do not add menu state that would compete for
  the same mount point.
- Saving or restoring progress — no persistence system exists.
- `Game_Over` — still unreachable; level advancement is not a fail state.
- Changing level budgets, wave counts, or seeding — `level_to_params` and
  `level_init` already own that.
- Removing `Level.flee_prohibited` — it is a test switch, separate from the
  transition.
- Retuning the transition as a difficulty ramp — 1.6 verifies replay, not feel.

## Outcome

Landed as planned, with these choices:

- **Hold duration.** `LEVEL_TRANSITION_TIME = 5.0`, marked TEMP until the skill
  tree. Held in `LevelTransition.duration` so the skill tree can take it over.
- **Trigger and ownership.** The `.Playing` branch checks `Level.level_end` after
  the wave block and switches to `.Level_Transition`; the transition branch
  owns the only later `level_init` call, using `level_number + 1` and the stored
  `master_seed`.
- **Reset policy.** Bullets are cleared; the player position is left in place.
  The return roster is untouched and survives.
- **Render.** The frozen world frame is drawn, then a blended black overlay
  ramps to alpha 220 over the first 10% of the hold, then the level text is
  drawn on top. There is no `RenderClear` in the transition render path.
- **Text.** `Level N Cleared` plus `Wait for next level`.
- **Removed.** `Level.end_chance`.
- **Accepted temporary cost.** `fmt.ctprintfln` and `fmt.caprintfln` allocate
  from the temp allocator every transition frame. This matches the debug
  overlay's existing pattern and is accepted until the skill tree replaces the
  transition UI.
- **Not recorded yet.** Runtime verification: exactly one start/end pair per
  level, correct level+1 generation, frozen simulation during the hold, roster
  survival, and same-seed replay. The checks are listed in `SESSION.md`.
