#+title: ABX! Roadmap

* ABX! Roadmap

Organized by category. Ordered by dependency within each category.

Categories marked [[file:docs/DECISIONS.md][Decisions]] reference the decision
that established the work.

** Current Slice

Level advancement and transition, plus the minimum needed to observe it.

*** Prerequisite: State and Input

- [ ] Gate per-frame updates in ~main~ on ~world.state~
  - Each state gets its own update set
  - ~.Menu~ renders only; ~.Playing~ runs simulation; ~.Level_Transition~ runs
    transition logic; ~.Paused~ / ~.Game_Over~ suspend simulation
  - Extract ~update_simulation~ so per-state update sets stay visible in one
    place rather than scattered through the loop
- [ ] Add event handling to leave ~.Menu~ and enter ~.Playing~
- [ ] Show a keybind hint on the menu so the entry action is discoverable
- [ ] Wire ~.Paused~ and ~.Game_Over~ minimally so no ~GameState~ variant is a
      dead enum value

*** Prerequisite: Seeding

- [ ] Add ~.Level~ to ~SeedCategory~
- [ ] Pass a globally monotonic wave number to ~derive_seed~ for the ~.Wave~
      category (replaces the hardcoded ~0~ in ~level_init~)
- [ ] Seed the per-level wave-count draw from the ~.Level~ category
- [ ] Seed the per-wave flee threshold from the ~.Level~ category
- [ ] Verify no seed collision across levels

*** Level and Wave Lifecycle

- [ ] Add ~wave_index~ to ~Level~ (position within current level), keeping
      ~wave_count~ as the global total; initialize both
- [ ] Draw a level's wave count by seeded random draw, range growing with level,
      clamped to ~MAX_WAVES~
- [ ] Initialize all drawn waves in ~level_init~
- [ ] Thread ~level_to_params(level)~ through, replacing the hardcoded ~1~
- [ ] Advance ~wave_index~ when the active wave resolves
- [ ] Mark the level complete when ~wave_index~ exceeds the level's wave count
- [ ] Fix the debug overlay, which currently renders ~wave_count~ as a permanent
      ~0~ because the field is never written

*** Wave Resolution

The actual core of the slice. Nothing currently detects that a wave has
finished.

- [ ] Add a flee threshold to ~Wave~, rolled once at ~wave_init~
- [ ] Track per-wave resolved count, incrementing on death or flee
- [ ] Complete the wave when resolved == ~spawn_count~ (not ~total_enemies~ —
      spawning may not be finished)
- [ ] Resolve the three cases explicitly: dead (resolved), fled (resolved and
      scheduled to return), still alive (unresolved)
- [ ] Decide wave membership tracking


** Known trap: ~wave.enemy_indices~ indexes the flat ~bacteria.cold[]~ pool, and slots are recycled by ~find_free_bacteria_slot~. Once fleeing-and-returning exists, a returning bacterium can land in a recycled slot and be double-counted as resolved for the wrong wave. Membership must move onto the bacteria themselves, or returning bacteria need their own pool.

*** Fleeing and Returning

The difficulty-escalation engine, not an escape valve.

- [ ] Flee remaining bacteria when remaining-alive drops below the rolled
      threshold; resolve the wave at that moment
- [ ] On flee, move bacteria into a pending roster on ~World~, not ~Level~
      - The roster survives level transitions; ~Level_Transition~ must not clear it
- [ ] Queue each fleeing bacterium for the *next wave*, positionally — flee again
      and it enters the wave after that
      - A level never opens with a flood; the backlog arrives one wave at a time
- [ ] Let carried bacteria flee again: fresh buff roll, fresh health restore, no
      escape counter
- [ ] On return, roll a resistance buff, restore health to spawn max, resume
      normal state
- [ ] Bound the roster against ~MAX_ENEMIES~; drop oldest when full
      - Carrying across levels makes this bound do more work than it did when the
        roster was level-scoped

**** Fleeing Prohibited

Required for the boss flush, though boss content is deferred. The roster cannot
be escaped on indefinitely, so the 5-slot cap is what keeps escalation bounded —
this is how that cap stops being exceeded.

- [ ] Add a fleeing-prohibited flag to ~Level~, set when a level is a boss level
- [ ] At such a level, do not roll a flee threshold and do not allow withdrawal —
      all bacteria must be destroyed before advancing
- [ ] Boss specifics deferred: separate level or special wave, whether the roster
      enters or is spent before the boss. See Decisions for the reasoning that is
      already settled.

** Do not drop the roster at level end. Fleeing on the final wave of a level would
otherwise be free — the level still completes and the bacteria are gone forever.
Since the final wave is where the flee threshold is most likely to cross, that
becomes the optimal strategy and defeats the whole escalation engine.**

**** Resistance Buffs

Strengthening is by resistance only. Bacteria never change species.

- [ ] Add a ~BuffCategory~ enum: ~Hardy~, ~Resistant~, ~Biofilm~, ~Frenzied~
- [ ] Hold buffs per-instance on ~BacteriaCold~ as a fixed-size array of
      ~(category, magnitude)~ pairs — 5 slots, a compile-time constant
      - Buffs cannot live in ~BACTERIA_DEFS~; it is ~const~ and species-indexed
- [ ] Add a separate ~BUFF_DEFS~ table with absolute magnitudes
      - Do NOT derive buff values from ~BACTERIA_DEFS~ — changing a bacterium's
        base health would silently rescale every buff
- [ ] Roll the category from the full set on each return; repeats allowed
- [ ] Restore health to spawn max on return, which may be buff-boosted
- [ ] Wire ~species_unlocked~ (~src/procedural.odin:124~) into spawning, so
      ~bacteria_spawn~ stops hardcoding ~.Strep~ (~src/level.odin:128~)
      - For spawn variety only; there is no promotion

** Note: base stats are still in progress and not final. Do not tune buff
magnitudes until they settle.**

** Two stacking risks, both blocking tuning rather than implementation:

- [ ] Frenzied stacking — a 5-stack Frenzied Pseudomonas at base speed 400,
      multiplied by a wave ~speed_scalar~ already scaling per level block
      (~src/procedural.odin:132~), risks an unplayable screen. Consider
      additive-with-cap rather than free multiplication.
- [ ] Resistant vs. weapon weakness — weapons deal 6 / 3 / 2 for effective /
      neutral / ineffective (~src/player.odin:37~). A Resistant bacterium with the
      wrong weakness could become effectively unkillable.

*** Level Transition

- [ ] Implement ~Level_Transition~ as a real state that does real work: hold the
      frame, show the level number, advance
- [ ] Make it the single owner of level progression: derive next level's seed,
      draw its wave count, initialize its waves, reset per-level state
- [ ] Confirm and remove ~Level.end_chance~, which appears superseded by the
      rolled flee threshold

*** Verification

- [ ] Seeded replay: same seed, two runs, identical wave composition,
      formations, flee thresholds, and return schedules
- [ ] Different seeds produce observably different runs
- [ ] Flee and return do not perturb determinism
- [ ] Confirm ~sdl.GetTicks()~ appears in no generation or threshold decision


** Verification is last by sequence, not by importance. Nothing in this slice is confirmed until it passes.

*** Open Questions

Blockers, not tasks. Each must be decided before the work that depends on it.

- [ ] **Does the flee threshold scale with buff count?** A carried bacterium
      returns at full health with up to 5 buffs. If it can flee the instant the
      threshold crosses, a heavily buffed bacterium barely participates and the
      buff system feels pointless. Blocks Fleeing and Returning.
- [ ] **At boss levels, disabled outright or permitted but buff-free?** Only
      "disabled" makes "clear all bacteria" mean what it says. Deferred with the
      rest of the boss specifics.
- [ ] **Does the roster enter the boss level or get spent first?** Letting it
      arrive makes the boss level the hardest thing in the game by design. Deferred.
- [ ] **Boss meter interaction** — independent of flee difficulty, or stacking?
      Two escalating systems can multiply and quietly break tuning.
- [ ] **Buff visual channel** — one outline per category is the current leaning,
      held loosely. Species color already carries identity, so buffs need their own
      channel. Not needed before the skill tree.

** Resolved since the last update

- Strengthening model — resistance buffs, not promotion. Bacteria never change
  species.
- Identity on return — kept. Same bacterium, same species.
- Tier promotion — removed entirely; nothing to gate.
- Return scope — roster carries across levels on ~World~, drains into the next
  wave positionally, and carried bacteria may flee again.
- Boss flush — bosses clear the roster; fleeing is prohibited there. Boss
  specifics deferred.

- [ ] **Flee threshold direction** — ~WaveParams.threshold = 0.8~
      (~src/procedural.odin:127~) is ambiguous between fraction killed and fraction
      remaining. Read as fraction remaining, 0.8 means bacteria flee while 80% are
      still alive, inverting the difficulty. Blocks Wave Resolution.

** Determinism

Tracked separately from the slice: mixing a timing refactor into an advancement
slice makes both harder to verify independently. See Decisions for the full rule.

- [ ] Split ~delta_time~ (~src/game.odin:431~) into real elapsed time for motion
      and a fixed-increment tick counter for decisions
- [ ] Convert ~formation_complete_time~ (~src/level.odin:146~) from
      ~sdl.GetTicks()~ to a tick count
- [ ] Fix the always-true dive gate at ~src/level.odin:157~ — it never gated
      anything, leaving ~formation_complete_time~ dead
- [ ] Make ~formation_complete~ (~src/level.odin:136-148~) tick-driven rather than
      derived from continuous motion; it is the one decision currently coupled to
      wall-clock timing
- [ ] Audit for further wall-clock reads feeding decisions

** Playability Gaps

Unrelated to the slice above; found while assessing current state.

- [ ] ~parse_args~ in ~src/cli.odin~ declares return type ~CLI_State~ with no
      terminating return on the fall-through path. Looks like a compile error, or
      the file is not in the build.
- [ ] ~Config.seed~ and ~Config.level~ are never populated by ~parse_args~; only
      ~--debug~ is handled, and any other argument prints ~WRONG~ and errors out.
      A ~--seed~ flag would make Verification much easier to exercise.
