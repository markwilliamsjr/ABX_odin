# ABX_odin
## Motivation
I've always found games fascinating, and the idea of making them even more so. This is my first attempt at making a game! It started as a small Galaga remake in C to learn fundamental game development. However, the more I worked on it, the more ideas started coming, and it evolved into a tactical Galaga-like shooter with procedurally generated levels built from a seed and a Path of Exile-style player leveling tree.

Along the way I've been focusing on data-oriented design, entity component systems, and DOOM-like architecture. C's verbosity and slow iteration speed became frustrating, so I switched to Odin and could focus on building the game rather than fighting the language. Here is the link to the last C version if you want to check out where it started: [ABX_C](https://github.com/markwilliamsjr/ABX_C/tree/main)

## AI Usage
No AI was used to generate any code or assets. All code was typed and all assets were created by me.

AI was used as an assistant to help keep track of what to do and when to do it, and to brainstorm ideas that fed into the final design. All design decisions are mine. The rules governing that are documented in [AGENTS.md](https://github.com/markwilliamsjr/ABX_odin/blob/main/AGENTS.md), which limits the agent to planning, debugging, note taking, code review, and organizing.
